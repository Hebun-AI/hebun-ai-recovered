# 06 — Runtime Inputs and Outputs

## Purpose

Define stable constitutional packages at the Runtime boundary without prescribing schemas, APIs, protocols, or transport.

## Runtime Inputs — Execution Admission Package

The required Runtime input preserves:

- approved objective and bounded responsibility;
- Director authority reference and applicable approval Scope;
- verified execution-plan reference;
- Governance Outcome and unresolved constraints;
- applicable Capability and realization references;
- eligible participant responsibilities;
- exact Enterprise Memory versions and restrictions;
- Tenant, organizational context, classification, and purpose;
- expected outcome and completion meaning;
- interruption, termination, failure, and escalation boundaries;
- contract identity, version, provenance, and correlation.

The package is not a workflow, command stream, task graph implementation, schedule, event, message, API payload, or blanket permission.

## Runtime Outputs — Runtime Outcome Package

The Runtime output preserves:

- originating admission and accepted responsibility;
- realized outcome class and declared completion status;
- attributable observations and evidence;
- consumed Memory version references;
- limitations, divergence, failures, and unresolved conditions;
- Governance and authority constraints encountered;
- interruption, suspension, termination, or escalation context;
- provenance, correlation, and audit references.

The output is not canonical truth, business acceptance, Governance approval, Director decision, Memory admission, recommendation, or authorization for further work.

## Rules

- **P21-CONTRACT-001:** Runtime must reject incomplete or incompatible admission packages.
- **P21-CONTRACT-002:** Input and output must preserve stable correlation and exact contract version.
- **P21-CONTRACT-003:** Runtime must not modify upstream approval, Governance, Memory, or plan artifacts.
- **P21-CONTRACT-004:** Outcome evidence must distinguish observation, limitation, failure, and conclusion.
- **P21-CONTRACT-005:** An outcome must not authorize continuation or new work.
- **P21-CONTRACT-006:** Package meaning must remain independent of representation or transport.

## Enterprise Example

An outcome package may state that responsibility completed with a limitation. It does not decide whether the business objective was achieved or admit observations into Enterprise Memory.
