# 03 — Runtime Principles

## Purpose

Define the durable principles governing operational realization.

## Principles

1. **Approved work only:** no responsibility is realized without explicit authority.
2. **Constitution before operation:** canonical architecture constrains Runtime.
3. **Faithful realization:** Runtime does not improve, reinterpret, or extend approved work.
4. **Least responsibility:** Runtime accepts only the minimum declared responsibility.
5. **Governance preservation:** applicable outcomes and constraints remain binding.
6. **Memory integrity:** exact admitted Memory versions and restrictions remain intact.
7. **Visible limitation:** missing capability, incompatibility, and failure remain explicit.
8. **Fail closed:** uncertainty about authority or boundaries never defaults to action.
9. **Traceable realization:** inputs, responsibility, outcomes, and failures remain attributable.
10. **Replaceability:** implementation change never changes constitutional identity.

## Rules

- **P21-PRINCIPLE-001:** Operational feasibility must not be treated as authority.
- **P21-PRINCIPLE-002:** Successful repetition must not become constitutional approval.
- **P21-PRINCIPLE-003:** Runtime optimization must not alter approved meaning or Scope.
- **P21-PRINCIPLE-004:** Memory consumption must preserve provenance, version, Tenant, classification, and lifecycle.
- **P21-PRINCIPLE-005:** Runtime evidence must remain observation, not canonical truth.
- **P21-PRINCIPLE-006:** Runtime must report and defer whenever faithful realization becomes impossible.

## Enterprise Example

A Runtime may determine that an approved responsibility cannot be realized within its declared limitation. Refusal is constitutional compliance, not failure to obey.
