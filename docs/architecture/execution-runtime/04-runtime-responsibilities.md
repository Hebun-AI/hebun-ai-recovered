# 04 — Runtime Responsibilities

## Purpose

Assign Runtime-owned responsibilities without absorbing adjacent architectural domains.

## Runtime-Owned Responsibilities

- validate the completeness and current applicability of the Execution Admission Package;
- accept or refuse bounded operational responsibility;
- preserve correlation to the approved authority and constitutional inputs;
- realize accepted responsibility faithfully within declared limits;
- preserve isolation, classification, and Memory constraints;
- maintain honest visibility into operational status classes;
- produce attributable observations, limitations, failures, and outcomes;
- honor interruption, suspension, termination, and escalation constraints;
- close accepted responsibility without implying business approval.

## Responsibilities Runtime Does Not Own

Runtime does not own reasoning, planning, decision, verification, Governance evaluation, approval, Capability identity, Agent constitution, Memory admission, domain intelligence, collaboration meaning, workflow definition, scheduling policy, event semantics, orchestration strategy, or deployment.

## Shared Boundary Responsibilities

Across an admission boundary, upstream owners and Runtime jointly preserve correlation, contract version, authority references, Scope, Governance evidence, Tenant, classification, Memory versions, expected outcome, and limitations. Shared preservation does not mean shared authority or ambiguous ownership.

## Rules

- **P21-RESPONSIBILITY-001:** Every Runtime obligation must have one accountable owner.
- **P21-RESPONSIBILITY-002:** Shared responsibility must not create shared authority.
- **P21-RESPONSIBILITY-003:** Runtime must not accept responsibility outside declared capability and constraints.
- **P21-RESPONSIBILITY-004:** Acceptance must not broaden the approved Scope.
- **P21-RESPONSIBILITY-005:** Completion reporting must not become business acceptance or approval.
- **P21-RESPONSIBILITY-006:** Adjacent-phase responsibilities must remain outside Phase 21.

## Enterprise Example

Runtime owns faithful realization and evidence for an admitted responsibility. The business owner retains outcome acceptance; Governance retains eligibility; the Director retains final authority.
