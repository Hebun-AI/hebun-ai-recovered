# 05 — Boundaries

The Director Interface is a **surface**, not a system of its own. It presents what Hebun's deeper capabilities produce and relays the Director's intent back into them. This document draws the line: the interface consumes the deeper systems and replaces none of them, and it holds no authority of its own.

## The interface consumes; it does not replace

Director Interface **never replaces**:

### Director Reasoning
The interface **presents** judgment; it does not **form** it. Recommendations, decision requests, and warnings shown through the interface are produced by [Director Reasoning](../../director-reasoning/README.md). The interface is the display and the relay — the thinking happens beneath it. An interface that reasoned would be doing reasoning's job badly and duplicating it.

### Organizational Memory
The interface **surfaces** history; it does not **hold or alter** it. Briefings, summaries, and recalled context shown through the interface are drawn from [Organizational Memory](../../memory/README.md), which remains the single durable record. The interface reads memory to present it; it never becomes a second memory, and it never rewrites the first.

### Multi-Agent Orchestration
The interface **requests and relays approval** for work; it does not **execute** it. When the Director approves an action, orchestration carries it out. The interface is where approval is asked and given — not where work runs. An interface that executed would have crossed out of being an interface.

## What the interface actually holds

The interface holds exactly one thing: the **presentation-and-relay** role. It:

- presents the deeper systems' outputs legibly, across modalities;
- carries the Director's questions, instructions, decisions, and approvals back down;
- proactively surfaces what matters ([04](04-proactive-assistance.md)).

It holds **no** judgment of its own, **no** durable state of its own, **no** execution ability, and **no** authority. Everything meaningful lives below it; the interface is how the Director reaches it.

## No authority of its own

This is the boundary that matters most. The Director Interface makes Hebun accessible and proactive — but accessibility is not authority.

- The interface **presents** recommendations; it does not **accept** them for the Director.
- The interface **carries** approvals; it does not **grant** them on the Director's behalf.
- Every irreversible or committing action routed through the interface still requires the Director's **explicit approval** ([Director Authority](../../director-reasoning/05-director-authority.md)), on whatever modality it is given.

A one-tap approval, a spoken "yes," a click — each is the Director exercising authority *through* the interface, never the interface exercising authority *for* the Director.

## Why the boundary holds

- **Separation of concerns.** Reasoning reasons, memory remembers, orchestration executes, the interface presents. Each stays clean because the interface does none of their jobs.
- **Trust.** A surface that cannot decide or act is a surface the Director can rely on completely — it can only ever bring things forward, never do them.
- **Authority.** Keeping the interface authority-free is what keeps authority with the Director. The most visible, most-used layer of Hebun is deliberately the one with the least power of its own.

The interface is the face of Hebun — and precisely because it is the face, it holds none of the power. It shows everything and decides nothing.
