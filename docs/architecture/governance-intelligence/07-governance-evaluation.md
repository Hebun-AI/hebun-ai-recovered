# 07 — Governance Evaluation

## Purpose

Governance Evaluation applies pre-qualified Policy, Authority, Compliance, Privacy, and Governance Rule references to a declared use of one immutable Reasoning Output Package.

## Evaluation Sequence

1. bind exact Reasoning Output Package and declared use;
2. resolve Governance Scope;
3. validate constraint identity, version, lifecycle, authority, and applicability;
4. create one Evaluation Unit per material constraint-to-use check;
5. record eligibility finding, condition, conflict, insufficiency, and limitation;
6. validate boundary compliance;
7. assemble one Governance Outcome;
8. preserve the complete Governance Trace.

This is a logical evaluation dependency, not a Runtime workflow.

## Evaluation Areas

- policy applicability and alignment;
- authority representation and reserved rights;
- compliance obligations and prohibitions;
- privacy, classification, minimization, retention, and disclosure;
- Tenant and organization boundaries;
- canonical architecture preservation;
- declared-use and audience eligibility;
- decision, recommendation, approval, execution, enforcement, and Runtime separation.

## Evaluation Integrity

Governance evaluates only the eligibility of declared use. It cannot re-evaluate evidence weight, inference validity, confidence correctness, reasoning strategy, Hypotheses, or Results. Suspected reasoning defects are preserved as input limitations or Review Required conditions, never repaired.

## Rules

- **GEVAL-001:** Every Evaluation Unit must bind one package subject, declared use, and applicable constraint.
- **GEVAL-002:** Governance Evaluation must remain independent from the reasoning it reviews.
- **GEVAL-003:** Eligibility and correctness must remain distinct.
- **GEVAL-004:** Evaluation must not modify package content, evidence, Trace, confidence, or Results.
- **GEVAL-005:** Conflicts, missing basis, uncertainty, and failed controls must remain visible.
- **GEVAL-006:** Material changes to use, Scope, package, or constraints require re-evaluation.
- **GEVAL-007:** Evaluation produces no recommendation, decision, approval, authorization, enforcement, or action.

## Enterprise Example

A supported Result proposes no action but contains restricted personal information. Governance may find internal restricted review conditionally eligible and external use ineligible. It does not reassess the Result's truth.

## Boundaries

No executable evaluation rules, policy interpreter, reasoning validator, workflow, or Runtime gate is defined.
