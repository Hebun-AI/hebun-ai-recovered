# 06 — Agent Authority Model

## Purpose

The Agent Authority Model prevents participation semantics from collapsing into authority semantics.

## Responsibility Separation

| Concept | Meaning | Agent boundary |
|---|---|---|
| Participation | Admitted contribution within Scope | Permitted when governed |
| Recommendation | Advisory preference with rationale | May only exist where prior canonical architecture permits it; never approval |
| Decision Support | Structured material for Director judgment | May be presented, never decided by the Agent |
| Approval | Explicit acceptance by the accountable authority | Prohibited |
| Decision | Authoritative selection among alternatives | Prohibited |
| Authorization | Permission for bounded committing activity | Prohibited |
| Execution | Realization of approved work | Prohibited in Phase 17 |
| Ownership | Accountability for an organizational subject | Prohibited |

Authority originates from canonical organizational and Director governance, not from intelligence, confidence, role labels, technical access, popularity, consensus, or Runtime capability.

## Least Participation

An Agent receives only the participation latitude necessary for its declared purpose, Tenant, and organizational context. Additional knowledge, technical ability, or access does not expand that latitude or permit cross-boundary use.

## Rules

- **P17-AUTHORITY-001:** Agent = Specialized Participant, never authority.
- **P17-AUTHORITY-002:** Participation must not imply permission, approval, or authorization.
- **P17-AUTHORITY-003:** Decision Support must terminate at the Phase 7E Director boundary.
- **P17-AUTHORITY-004:** Agent consensus must not become organizational authority.
- **P17-AUTHORITY-005:** Technical access must not be represented as architectural authority.
- **P17-AUTHORITY-006:** Authority uncertainty requires escalation and suspension of the affected contribution.
- **P17-AUTHORITY-007:** Access to another Tenant or organizational context must not imply authority to participate within it.

## Anti-Pattern

“The validator approved the architecture because all checks passed” is invalid. Validation reports conformance evidence; only the Director can approve canonical architecture.
