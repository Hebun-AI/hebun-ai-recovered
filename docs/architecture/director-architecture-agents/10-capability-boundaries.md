# 10 — Agent Capability Boundaries

## Purpose

This document preserves the separation among Agent identity, enterprise Capability, eligibility, binding, realization, execution attachment, and Runtime.

## Canonical Separations

- Capability ≠ Agent
- Agent role ≠ Capability ownership
- Agent eligibility ≠ Agent–Capability binding
- Binding ≠ participation admission
- Participation ≠ execution authorization
- Capability realization ≠ Runtime operation
- Agent lifecycle ≠ Capability lifecycle
- Agent replacement ≠ Capability retirement

An Agent may be considered as a future realization participant for one or more Capabilities only through the Phase 10 governed binding model. Phase 17 neither creates a Capability catalog nor authorizes any binding.

## Capability Envelope

Agent participation must remain bounded by declared competence, evidence, limitations, architecture Scope, governance constraints, accountability, and escalation obligations. A claimed competence is not proof of Capability, permission, or authority.

## Runtime Boundary

Phase 17 participation does not execute. A future Agent acting as a Capability realizer may execute only through a separately authorized execution attachment and the Phase 8/21 Runtime boundary. Eligibility for constitutional participation does not grant that attachment, and an execution attachment does not grant advisory, review, validation, escalation, or decision-support authority. Runtime may change without changing the Agent constitution or Capability identity.

## Rules

- **P17-CAPABILITY-001:** No Agent may be modeled as an enterprise Capability.
- **P17-CAPABILITY-002:** Agent specialization must not create Capability ownership.
- **P17-CAPABILITY-003:** Eligibility must not be treated as binding or authorization.
- **P17-CAPABILITY-004:** Agent replacement must preserve Capability identity and historical evidence.
- **P17-CAPABILITY-005:** Phase 17 must not create an execution attachment.
- **P17-CAPABILITY-006:** Runtime behavior must not redefine Agent constitutional responsibility.
- **P17-CAPABILITY-007:** Participation and execution attachment must remain separately governed and must not confer authority upon each other.

## Enterprise Example

Multiple future Agents may support architecture validation. The Architecture Validation Capability remains stable when an Agent is suspended, retired, or replaced.
