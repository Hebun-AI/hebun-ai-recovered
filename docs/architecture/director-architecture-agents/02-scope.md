# 02 — Phase 17 Scope

## Purpose

This document fixes the inclusion and exclusion boundary of Phase 17 so that constitutional Agent participation is not mistaken for concrete Agent design or operational behavior.

## Included

- Director-facing participation principles;
- architecture-specialist role archetypes;
- participation, authority, lifecycle, escalation, human-review, and Capability boundaries;
- universal constitutional rules;
- compatibility with completed canonical architecture;
- review criteria for future Agent proposals.

## Excluded

- Finance, HR, Sales, Marketing, Legal, Operations, Customer Success, Platform, or other business-domain Agents;
- concrete Agent instances, registries, identities, rosters, teams, or topologies;
- Agent-to-Agent communication, delegation, handoff, negotiation, consensus, shared memory, or coordination;
- reasoning, recommendation, decision, approval, planning, execution, workflow, Runtime, tools, deployment, or infrastructure;
- schemas, APIs, prompts, models, algorithms, storage, telemetry, state machines, or implementation.

## Boundary Tests

A concept is in scope only if it constrains how every future Agent may participate. A concept is out of scope if it selects a concrete Agent, causes work, orders activity, transmits tasks, stores operational state, or assigns business-domain responsibility.

## Rules

- **P17-SCOPE-001:** Phase 17 must define constitutional constraints, not operational mechanisms.
- **P17-SCOPE-002:** Business-domain specialization belongs to Phase 18.
- **P17-SCOPE-003:** Communication and delegation belong to Phase 19.
- **P17-SCOPE-004:** Shared memory and coordination belong to Phase 20.
- **P17-SCOPE-005:** Runtime realization belongs to Phase 21 and later.

## Risk

Terms such as “participation” and “lifecycle” can sound operational. In Phase 17 they describe admissibility and governance states only, never a Runtime sequence or automated process.
