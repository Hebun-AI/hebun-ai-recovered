# 06 — State Constitution

## Purpose

Define State as a traceable representation of current operational condition.

## Constitutional Identity

State is the attributable, time-contextual representation of the current operational condition of one admitted Runtime responsibility or one constitutionally identified Workflow concern.

State is not a state machine, transition mechanism, canonical architecture, Enterprise Memory, Governance authority, decision, command, event, cache, database record, or implementation object.

## Constitutional Duties

State must preserve subject identity, valid observation boundary, effective time context, source evidence, provenance, authority and Governance constraints, Tenant, classification, version, uncertainty, and relationship to prior State.

## Authority Limits

State describes condition. It cannot authorize progression, execution, scheduling, transition, recovery, approval, or policy change.

## Rules

- **P22-STATE-001:** Every State must identify one bounded operational subject.
- **P22-STATE-002:** State must be evidence-based, time-contextual, and attributable.
- **P22-STATE-003:** State must never become Governance or Director authority.
- **P22-STATE-004:** Missing or conflicting evidence must remain explicit.
- **P22-STATE-005:** State must not be treated as Enterprise Memory without separate admission.
- **P22-STATE-006:** State meaning must remain independent of representation technology.

## Enterprise Example

A State may describe an admitted responsibility as constrained at a particular observation boundary. It cannot waive the constraint or cause progression.
