# 02 — Workflow Constitution

## Purpose

Define Workflow as a constitutional representation of operational progression.

## Constitutional Identity

A Workflow is a bounded, attributable representation of how one admitted Runtime responsibility progresses from accepted responsibility toward a declared terminal meaning.

Workflow is not execution, a plan, task assignment, schedule, orchestration, workflow engine, state machine, message exchange, protocol, or authority.

## Constitutional Duties

A Workflow must preserve:

- originating Runtime admission and responsibility;
- objective, Scope, authority, Governance, Tenant, and classification;
- permitted progression meanings and constraints;
- required evidence and expected outcome;
- current State references and relevant Event references;
- divergence, suspension, termination, and failure visibility;
- provenance, version, ownership, and correlation.

## Authority Limits

Workflow may represent eligible progression. It cannot approve, decide, plan, schedule, execute, reassign responsibility, waive Governance, change Memory, or expand Runtime admission.

## Rules

- **P22-WORKFLOW-001:** Every Workflow must bind to exactly one admitted Runtime responsibility.
- **P22-WORKFLOW-002:** Workflow identity must remain distinct from Runtime, execution, and implementation.
- **P22-WORKFLOW-003:** Workflow progression must preserve all admission constraints.
- **P22-WORKFLOW-004:** Workflow must not create tasks, authority, approval, or execution Scope.
- **P22-WORKFLOW-005:** Divergence and blocked progression must remain explicit.
- **P22-WORKFLOW-006:** Workflow representation must remain implementation-independent.

## Enterprise Example

A Workflow may represent that an approved report progressed from admitted to evidence preparation. It does not perform analysis, schedule work, or authorize publication.
