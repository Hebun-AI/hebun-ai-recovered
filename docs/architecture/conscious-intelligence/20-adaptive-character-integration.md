# 20 — Integration with Adaptive Character Engine

## Dependency Status

No canonical Adaptive Character Engine architecture was found in this repository. This document defines a safe personalization boundary only.

## Permitted Integration

A future Adaptive Character Engine may use explicitly approved, low-risk communication preferences such as:

- desired level of detail;
- preferred language;
- formal or informal tone;
- accessibility needs;
- learning pace;
- preferred reflection format;
- explicitly requested interaction boundaries.

It may adapt presentation, not identity or truth.

## Prohibited Integration

It must not:

- make Heby claim a personality, emotion, attachment, need, memory experience, or personhood;
- simulate jealousy, affection, disappointment, suffering, loneliness, or dependency;
- optimize style for persuasion or retention;
- infer vulnerabilities from personal history;
- use sensitive values, faith, health, relationships, or grief to increase compliance;
- claim a relationship deeper than the user-approved functional context;
- conceal that adaptation is system behavior.

## Contract

The integration receives only:

- approved preference identity;
- applicable scope;
- provenance and confidence;
- sensitivity classification;
- effective and review dates;
- revocation status;
- prohibited adaptation boundaries.

It returns an adaptation rationale that is inspectable and reversible.

## Continuity Boundary

Stable presentation across time can support continuity, but stable presentation does not create a continuing self. If a preference changes, the prior version remains historical context but is not applied as current.

## Acceptance Gate

No implementation may connect personal memory to adaptive behavior until the canonical engine contract, anti-manipulation rules, sensitive-data exclusions, explanation model, and revocation propagation are approved.
