# 03 — Long-Term Memory Intelligence

## Definition

Long-Term Memory Intelligence governs how continuity-relevant information is classified, validated, retained, consolidated, challenged, archived, restored, and used over time.

It extends—not replaces—the canonical Organizational Memory architecture.

## Memory Classes

| Class | Purpose | Durability |
|---|---|---|
| **Temporary Memory** | Short-lived context pending immediate completion or review | Expires by default |
| **Working Memory** | Active context for a bounded objective | Session- or objective-bound |
| **Episodic Memory** | User-approved record of an event in context | Governed long-term |
| **Semantic Memory** | User-approved durable meaning, preference, or learned fact | Governed and version-aware |
| **Organizational Memory** | Durable enterprise events, decisions, lessons, and context | Existing canonical memory contracts govern |
| **User-approved Permanent Memory** | Explicitly approved continuity record with ongoing purpose | Long-term, reviewable, revocable from use |
| **Archived Memory** | Inactive memory retained for historical, legal, or user-directed reasons | Excluded from ordinary use until governed restoration |

## Required Memory Attributes

Every memory item requires source, owner, confidence, timestamp, evidence, sensitivity, retention policy, review status, version history, and revocation capability. It must also preserve scope, provenance, purpose of use, lifecycle, and integrity status.

## Memory Integrity Gate

No permanent memory may be created unless:

- the owner and source resolve;
- user approval is explicit where personal memory is involved;
- evidence and timestamp are sufficient for the claim type;
- sensitivity and allowed purpose are classified;
- retention and review obligations are defined;
- workspace and person boundaries are enforced;
- contradiction and duplication checks complete;
- the item conforms to canonical memory contracts.

## Governed Operations

- **Consolidation** creates a new derived summary linked to every contributing memory; originals remain.
- **Pruning** removes an item from active selection because it is expired, irrelevant, revoked, low-integrity, or duplicated; it does not silently erase history.
- **Contradiction detection** records incompatible memories without choosing one as truth.
- **Confidence adjustment** creates a versioned assessment with rationale and evidence.
- **Expiration** ends ordinary use under the retention policy.
- **Archival** moves a memory to inactive governed retention.
- **Restoration** returns an archived memory to eligible use after authority, purpose, integrity, and consent revalidation.
- **Revocation** withdraws permission for future use or access; legal/audit retention, if applicable, must be minimal and isolated.

## Boundaries

Memory ≠ Truth, confidence ≠ certainty, consolidation ≠ rewriting, pruning ≠ falsifying history, archive ≠ deletion, and restoration ≠ renewed truth.

## Enterprise Example

A strategic decision memory later conflicts with a retrospective account. Both remain with provenance. A new contradiction finding and user-approved annotation explain the difference. A consolidated lesson may reference both, but cannot replace either.
