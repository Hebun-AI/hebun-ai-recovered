> **Truth model.** A descriptor is not a connection. A capability declaration is not a capability. A seeded model record is not a live model target. ## 1. Executive summary

R1 gave Hebun a real, durable, tenant-isolated foundation. R2 must give Hebun its **first real model connectivity** — a Heby answer that is generated by a live provider, validated, and durably persisted — **without** enabling execution, Computer Use, integrations, or a second provider architecture.

The single most important finding: **there are two distinct "provider" worlds in this repository, and R2 belongs to only one of them.**

1. An **agent / execution provider framework** — `provider-framework`, `providers/{claude,codex,browser,github}`, `provider-invocation`, `provider-routing`, `provider-matrix`, and `runtime-activation`. Its Claude descriptor declares `Terminal`, `File System`, `Code Generation` capabilities; its invocation lifecycle stops at `Ready`; its activation engine is a deterministic evaluator over seeded decisions. This is **Computer-Use / coding-agent / execution** substrate. It is **R3 territory** and must not be hijacked for text generation.
2. A **Heby model-generation seam** — `heby-runtime/model-adapter.ts`, whose own banner calls it *"the single seam a future, separately-authorized, server-side live runtime would replace."* Its contract already types `ResponseOrigin = "deterministic" | "model"` and already enforces the invariant that *"model output … is UNTRUSTED and advisory — it never becomes evidence, authority, approval, policy, memory, or execution."*

**R2's correct target is world #2.** The narrowest architecturally correct slice completes the Heby model-adapter seam with a dedicated, server-only Claude *text* client behind a fail-closed availability gate, persists the validated answer to the **existing tenant-scoped `conversations`/`messages` schema**, and leaves the agent/execution framework, `heby-actions` execution gate, and all tool side-effects untouched.

No AI SDK is installed. No network call exists anywhere in `src`. Heby currently runs **client-side** and holds no secret, so R2 must also introduce a **server boundary** for the model step (mirroring the R1 pattern). A real Anthropic call is an external spend + credential gate that R2 implementation must stop before.

## 5. runtime-activation audit

`activation-engine.ts` exposes `evaluateActivation(runtimeDecision)`, composing environment / credential / policy / approval / risk / readiness / gate assessors into an `ActivationDecision` with an `ActivationLevel` (`Blocked | Simulation | Read Only | Dry Run | Ready For Live | Live Enabled | Emergency Disabled`). It is exported as `activationDecisions = runtimeDecisions.map(evaluateActivation)` — i.e. it runs at module load over a **static seeded array** from `@/features/runtime-boundary`, timestamped at a fixed `EPOCH`.

Key facts:
- **Not tenant-aware.** Input is a `RuntimeDecision` (seeded), not a `TenantContext`.
- **Never reaches live.** Best case is `Ready For Live`, whose own explanation says *"live execution remains disabled in this phase."* `Live Enabled` is defined but unreachable.
- **Credential gate is a concept, not a store.** `assessActivationCredentials` reads `runtimeDecision.credential.{required,state,note}`; `liveEligible` when `state === "Injected"`. There is no real secret behind it (`runtime-boundary/runtime-credentials.ts`).
- **It is coupled to the agent/execution runtime**, not to Heby text generation.

**Is runtime-activation the correct authority to enable the first provider?** For **execution** (R3): yes, it is the designed activation authority and should be reused there. For **R2 (Heby text answer)**: **no, not as-is.** Tying read-only text generation to an execution-activation engine that carries risk/approval/emergency-stop semantics over seeded agent decisions would (a) not be tenant-aware, and (b) risk execution semantics leaking into a read-only path. The correct R2 owner is the **`heby-runtime/model-adapter` seam** (its designed purpose), applying runtime-activation's *patterns* (env gate, credential gate, fail-closed) at Heby scope — **not** a parallel activation engine and **not** a bypass of the existing one for its own domain.

## 17. Security

- **Server-only invocation.** The model call, credential read, and persistence must run server-side. Heby is client today; R2 adds the server boundary. The API key is read only in the server resolver and never serialized to the client bundle (R1 pattern proven).
- **No client authority.** Tenant, provider, and model identity must be resolved server-side from the R1 session — never accepted from client input. (R1 already proves client-supplied tenant is not trusted.)
- **Prompt-injection boundary.** Retrieved evidence is data, not instructions; the existing contract keeps model output UNTRUSTED and forbids it from becoming evidence/authority/tool-trigger. Evidence identity comes only from the retrieval layer.
- **Tool escalation.** Model output cannot invoke tools (`INVOKABLE_SIDE_EFFECTS = ["READ_ONLY"]`, no tool runs "because a model suggested it").
- **Error leakage.** Provider errors are mapped to safe categories; raw provider errors and keys are never surfaced.
- **Rate / cost abuse.** Server-side per-request caps + a fail-closed budget gate (R2D); one-shot (non-streaming) simplifies bounding.

## 18. Execution separation (critical)

Connecting Claude for **answer generation** does **not** enable actions, mutations, dispatch, Computer Use, browser control, shell, device runtime, or integrations. Proof:

- R2 text-gen extends `heby-runtime/model-adapter` only. It never touches `heby-actions/execution-gate` — *"the only place a Heby action ever runs,"* which invokes **only** READ_ONLY and withholds every mutation (`REQUIRES_HUMAN_REVIEW`), device action (`RESTRICTED`), and substrate-less action (`UNAVAILABLE`).
- The agent `provider-invocation` `Ready → Invoking` transition stays unused; the agent Claude descriptor (Terminal/FileSystem) is not the R2 vehicle.
- `device-runtime` registry stays empty; no integration adapter exists or is added.
- Contract invariant: model output "never becomes … execution."

**Gates that remain closed:** heby-actions execution-gate, provider-invocation live transition, device-runtime, integrations, Computer Use, governance/decisions consequential-authorization.

## 19. Failure modes (fail-closed design)

| Condition | User-visible state | Internal classification | Retry? | Persists? |
|---|---|---|---|---|
| missing API key | "Model not connected" | `no-credentials` | no | no |
| invalid API key | "Model unavailable" | `provider-unavailable` (401 mapped) | no | no |
| provider timeout | "Model timed out" | `provider-timeout` | bounded (≤1) | no |
| rate limit | "Temporarily unavailable" | `rate-limited` (429) | backoff, bounded | no |
| model unavailable | "Model unavailable" | `provider-unavailable` (404 model) | no | no |
| malformed response | falls back to deterministic answer | `invalid-response` (validator rejects) | no | no |
| network failure | "Model unavailable" | `provider-unavailable` | bounded | no |
| tenant missing | denied | R1 fail-closed (`forbidden/tenant`) | no | no |
| session invalid | redirect `/login` | R1 fail-closed | no | no |
| budget exceeded | "Model paused (budget)" | `budget-exceeded` | no | no |
| provider disabled | deterministic-only | `no-provider-configured` | no | no |

On any model failure, Heby returns the **deterministic evidence-grounded answer** with an honest model-unavailable note — it never fabricates a model answer and never persists a failed generation as if successful.

This is narrower and safer than routing through the agent provider-invocation framework, and it fills the seam the code already designates.

Use a **fake transport** (injected Claude client returning canned responses/errors) for all but one test:

2. missing credential → `no-credentials`, fail closed

9. usage extraction (tokenCount from usage)
10. persistence across repository re-instantiation (durable conversation/message)
11. provider error mapping (401/429/404/5xx → safe categories)

13. no secret leakage (key never in client bundle / logs / response)
14. no execution escalation (heby-actions untouched; READ_ONLY only)
15. full existing suite regression (currently 260/260)

**The ONE test requiring a real Anthropic call:** a gated live smoke test (`R2D`) that performs a single minimal Messages call and asserts a validated, persisted answer. **Not run in R2A**, and only after the live-call gate is authorized.

## 22. Live-call gate

A real Anthropic call = external spend + credential exposure. R2 implementation **must stop before the first live call** until the Director authorizes, in one explicit decision: **provider** (Claude), **credential availability** (key present server-side), **live model** (explicit id), **budget ceiling** (max spend), and **maximum test calls** (e.g. ≤N). ## 23. UI impact

Heby's model boundary transitions from an honest **"model unavailable / not connected"** to a **truthful connected state only when runtime evidence proves it** (`isModelAvailable()` becomes true only when the gate passes and a real call succeeded in that request).

- **Provider/model state:** shown in the Heby panel header/status (and, longer term, a Platform provider surface).
- **Generated answer:** in the Heby panel body, with an **origin badge** (`deterministic` vs `model`) so model prose is never styled as authoritative truth.
- **Provenance:** the existing provenance/limitations display is reused; model answers carry "advisory, model-generated, validated" limitations.
- **Error display:** honest per-failure states from §19.
- **Streaming:** **defer.** One-shot validated answers are simpler and safer to validate-before-display; streaming complicates the untrusted-output validation contract and is not justified for R2.

No workspace redesign.

## 31. Risks

- **Framework confusion** — routing Heby text-gen through the agent provider-invocation/`runtime-activation` framework would drag in execution semantics and Computer-Use-shaped capabilities. Mitigation: use the model-adapter seam only.
- **Untrusted-output leakage** — model prose treated as evidence/authority. Mitigation: the existing contract invariant + `response-validator`; evidence identity stays retrieval-owned.
- **Secret exposure** — key reaching the client (Heby is client today). Mitigation: server boundary; server-only resolver (R1 pattern).
- **Fabricated cost/usage** — showing seeded numbers as live. Mitigation: only real `response.usage`; cost labeled derived.
- **Silent persistence gap** — answer lost on restart. Mitigation: durable `conversations`/`messages` repo, fail closed.
- **Scope creep into execution** — enabling tools/actions. Mitigation: `heby-actions` and all non-READ_ONLY gates stay closed and tested.
