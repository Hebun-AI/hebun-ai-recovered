## 5 · Continuity mechanism (narrowest form)

Implemented as text in `hebun-loop.md` only — no new authority, no automation:

1. Repository closure stays authoritative (§16.1, §21, §22 unchanged in meaning).
2. At **Persist**, after the closure exists on the phase branch, the phase writes one human-readable
   learning/decision summary into the Brain under `.hebun-brain/CONVENTIONS.md`: evidence links back to
   Git (commit, closure path), deferred risks only as pointers to §22, unverified claims labelled.
3. At **Close**, the report keeps four facts apart: repository committed · Obsidian written · GitHub
   pushed · production deployed. Brain writing is never a commit and never a gate.
4. `HEBUN_REPO=<phase worktree> python3 .hebun-brain/hebun_brain_sync.py validate` and `pending` run
   read-only against the repository.

**Not implemented (proposed boundary):** a hook, background sync or plugin that writes the vault
automatically would need broad filesystem permission outside the repository and a new integration.
If wanted later: a post-closure, read-only `pending` report only, never an authoring writer; the Brain
never feeds the repository.
