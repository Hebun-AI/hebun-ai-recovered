## What this document is, and what it is not

This is a **derived catalog** of what has already been designed, planned, deferred or intentionally
reserved for future Hebun. It exists so the Director can inspect the future system from A–Z and
decide, deliberately, whether anything important is missing.

**It is not an authority.** Listing a capability here **opens nothing, authorizes nothing, and
schedules nothing**. Every item below already lives in a repository document that owns it; this page
points, it does not absorb. Where this catalog and an authority disagree, the authority wins.

**Nothing in this document is available today.** For what exists, see
`HEBUN-CURRENT-SYSTEM-REALITY.md`.

## 2. Constitutional Programs — architecture published, runtime absent

These define what Hebun is constitutionally permitted to become. **All are marked
`COMPLETE / PUBLISHED` as architecture.** That means the governing document is finished — not that
any code exists.

### Program IV — Enterprise Orchestration · Phases 25–29
*Published.* Enterprise Work identity and lifecycle; Task and Activity beneath Work; planning and
prioritization without execution authority; delegation, coordination, handoff and escalation;
capability demand, resource eligibility and allocation.

**Partially realized in runtime.** Organizational Work Authority, recorded work, work evidence
references and purpose-bound governed acts are released. Planning, delegation and resource
management are not.

### Program V — Enterprise Security · Phases 30–36
*Published.* Enterprise identity, trust and permissions; runtime and execution security; **AI
security**; enterprise security operations; policy and continuous security governance.

**Runtime state: `DESIGN ONLY`** — the delivery authority's own words. This is the **largest
architecture-to-runtime gap in the system**, and the three missing authorities it would create
(permission, policy, security event/finding/incident) are the same three named as unavailable today.

### Program VI — Enterprise Reasoning · Phases 37–39 · **Status: OPEN**
Enterprise-wide reasoning beyond architecture-specific reasoning; enterprise evidence identity and
traceability; **decision intelligence that prepares decision material without replacing Director
authority.**

This is the **only Program still marked OPEN** rather than published.

### Program VII — Computer Use · Phases 40–43
*Published.* Bounded interaction with computer environments; authority, approval, traceability and
safety for computer-mediated execution; the constitutional limits of automation; integration with
enterprise systems without transferring authority.

**No runtime exists.** Hebun today observes providers through HTTP APIs under standing
authorization; it does not drive a computer.

### Program VIII — Organizational Intelligence · Phases 44–47
*Published.* Organizational learning; optimization intelligence **without execution authority**;
strategic awareness of position, change, risk and opportunity; strategic enterprise evolution
**without automatic roadmap authority**.

### Program IX — Enterprise Intellectual Evolution · Phases 48–51
*Published.* Knowledge assimilation and multi-source synthesis (documents, books, research, videos,
conversations); principle, pattern and comparative intelligence; enterprise wisdom; **Director
learning continuity**.

### Future Product Architecture — Enterprise Knowledge Graph & Decision Timeline
**Status: FUTURE PRODUCT ARCHITECTURE CAPABILITY — NOT OPEN.** No Program number, no Phase number.
The Enterprise's intellectual history as a navigable graph — why a decision was made, what it
affected, which constitutional rules influenced it, what depended on it.

Its declared separations are the point: `Timeline ≠ Enterprise Memory` · `Knowledge Graph ≠ Runtime`
· `Visualization ≠ Knowledge` · `Relationship ≠ Authority` · `Navigation ≠ Decision`.

## 6. What must never become a second authority

Recurring constraints, stated across the architecture and worth collecting in one place. Each is a
separation that future work must preserve:

- **Timeline ≠ Enterprise Memory** · **Knowledge Graph ≠ Runtime** · **Visualization ≠ Knowledge** ·
  **Relationship ≠ Authority** · **Navigation ≠ Decision**
- **Reachability ≠ authorization.** A process permitted to *reach* production is not thereby
  permitted to *mutate* it.
- **A derived observation is not an operations capability.** Security Center observes; it does not
  operate.
- **Optimization intelligence carries no execution authority**; strategic evolution carries **no
  automatic roadmap authority**; decision intelligence **prepares material, it does not replace
  Director authority**.
- **A table is not an authority.** `organizations` and `departments` have existed since the
  foundation baseline with zero readers and zero writers.
- **Enterprise Security & Trust reuses existing authorities** rather than creating rival ones.

# DIRECTOR REVIEW — POTENTIAL CAPABILITY GAPS

> **This section is not roadmap truth.** It is an analytical review derived from the inventory above,
> written to give the Director something concrete to react to. **Nothing here is authorized,
> scheduled, or promoted by appearing in this list.** Several entries argue *against* themselves.

---

### G1 · Permission & Policy runtime
**Why it might matter.** Three of the system's most-cited unavailable authorities are permission,
policy, and security event/finding/incident. Governance decides and records; nothing *evaluates*
permission at runtime. Every future execution capability is gated behind this.

**Would extend:** Program V (published, Phases 30, 34) · backlog 13 & 14 · Governance workspace.
**Requires:** new capability + new phases — architecture already exists, so **no new program**.
**Risks:** the largest build in the catalog; a permission engine that fails open is worse than none.
**Why it may be unnecessary:** Hebun's surfaces are read-only or ceremony-gated, so nothing is
currently exposed by its absence.
**Recommendation: INVESTIGATE** — it is the structural blocker behind most Era III work.

---

### G2 · The observation → action gap
**Why it might matter.** Hebun can now observe unattended, and TRH-20 proved the path from
observation to proposal. The agent abstained because there was nothing to reason from. The system
can *see* and can *propose*, but the join is unexercised.

**Would extend:** Agent Mandate Authority + Organizational Work Authority.
**Requires:** likely **no new architecture** — the authorities exist.
**Risks:** building against 0/0/0 evidence produces a mechanism nobody can evaluate.
**Why it may be unnecessary:** it is **data-blocked, not capability-blocked**. Waiting is correct.
**Recommendation: DEFER** — until observed reality contains something worth proposing about.

---

### G3 · Windowed evidence as a general primitive
**Why it might matter.** `ASA-2` is blocked on it; agent evidence cannot express before-and-after.
Meanwhile Social Intelligence *did* build windowed comparison (YT-SOC2, IG-AN2) — for providers
only. The same shape is missing for agents.

**Would extend:** agent-outcome-observation / evaluation.
**Requires:** new capability; **no new program**.
**Risks:** a premature generic "windowing" abstraction across unlike domains — precisely what the
provider derivations deliberately refused.
**Why it may be unnecessary:** each domain may deserve its own honest module, as Instagram and
YouTube did.
**Recommendation: INVESTIGATE** — narrowly, for agents; **not** as a universal primitive.

---

### G4 · Internal organizational structure
**Why it might matter.** Departments, teams and reporting lines are unavailable; the tables have
existed from the foundation baseline with zero readers and writers. Several planned capabilities
(department recommendation, organizational simulation, delegation) presume this exists.

**Would extend:** Organization Authority · Program IV Phase 28.
**Requires:** new capability; architecture published.
**Risks:** an org-structure authority nobody maintains becomes stale fiction — the exact failure L1
spent a release removing.
**Why it may be unnecessary:** OSA phases already delivered department identity, placement, people
register and composition. **The gap may be narrower than the label suggests.**
**Recommendation: INVESTIGATE** — starting by measuring what OSA already covers.

---

### G5 · Communications, calendar, CRM, finance, HR
**Why it might matter.** The prompt's search categories name these; Program IV Phase 18 names
Finance, HR, Sales, Marketing, Legal, Operations and Customer Success **agent domains** as published
architecture.

**Repository evidence:** an outbound email send exists (governed, executed once under permit). There
is **no calendar, CRM, finance or HR capability**, and no provider for any of them.
**Requires:** a new provider per domain — contract, capability, transport, credential kind.
**Risks:** each is a full provider program; four connectable providers took the system a long time.
**Why it may be unnecessary:** none is blocking anything measured today.
**Recommendation: DEFER** — and if one is ever chosen, pick it from customer reality, as TRH was.

---

### G6 · Observability of Hebun itself
**Why it might matter.** Backlog 18 (Observability Center) and Phase 23 both cover it. The system
just lost an observation cycle to a database connect that timed out, and the only reason it was
caught is that a human went looking. There is **no alerting on a failed scan**.

**Would extend:** Operations workspace · Runtime & Signals.
**Requires:** new capability; **no new program**.
**Risks:** an alerting system with no one on the other end is theatre.
**Why it may be unnecessary:** the failed cycle self-healed on the next tick — the system is
resilient by cadence rather than by monitoring.
**Recommendation: INVESTIGATE** — narrowly: the honest question is not "build observability" but
"should a failed scan be visible to anyone".

---

### G7 · Computer Use
**Why it might matter.** Program VII is fully published (Phases 40–43) and has **no runtime
whatsoever** — the largest published-but-unbuilt capability after Program V.

**Requires:** substantial new capability; architecture already exists.
**Risks:** the highest-blast-radius capability in the catalog — computer-mediated execution with
real-world effect, against a system that has no permission authority (G1).
**Why it may be unnecessary:** provider APIs under standing authorization have served every need so
far, with far better provenance than screen interaction.
**Recommendation: DEFER** — and explicitly behind G1. Executing against a computer without a
permission authority inverts Hebun's own principle that authority precedes automation.

---

### G8 · Enterprise search across workspaces
**Why it might matter.** Hebun holds knowledge, decisions, work, agents, observations and audit — and
there is no cross-workspace way to ask "everything about X". Heby grounds per source class, one at a
time.

**Would extend:** Heby · Knowledge.
**Requires:** new capability; possibly no new architecture (Phase 15, Architecture Query
Intelligence, is published).
**Risks:** a search surface that spans authorities is where provenance most easily goes missing —
results from six classes rendered as one list, each needing its own truth qualifier.
**Why it may be unnecessary:** Heby already answers grounded questions; the gap may be presentation,
not capability.
**Recommendation: PROBABLY REDUNDANT** at this stage — revisit once more classes carry evidence.
